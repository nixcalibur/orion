# ORION — Simulated pilot walkthrough

A concrete, reproducible look at how ORION reviews a submission end to end,
plus batch throughput data. Numbers below are generated by the real pipeline
(deterministic mock extractor, offline) — reproduce them with:

```bash
ORION_LLM_PROVIDER=mock ORION_EXTRACTION_VOTES=1 python main.py dataset/held_out_pep_noedd/submission.json
```

## Batch throughput

| Metric | Value |
|---|---|
| Held-out packs evaluated | 12 |
| Wall time (mock, offline) | 0.03 s (~3 ms/pack) |
| Classification accuracy (mock) | 11/12 |

The mock is a keyword heuristic (no API calls), so these numbers show pipeline
wiring cost, not LLM cost. With the real LLM and majority-vote ×3, the same
batch is ~36 extraction calls — minutes of wall time, versus the **4–6 hours
per submission** a manual review takes.

## Worked example — Cascade Payments UAB (`held_out_pep_noedd`)

**Submitted:** payment processor, Lithuania. JSON metadata + 3 documents
(AML policy, audited financials, beneficial ownership).

**What ORION found (extracted profile → deterministic score):**

| Dimension | Value | Score |
|---|---|---|
| Ownership | clear (natural-person UBOs) | 0 |
| AML policy | present (formal policy, MLRO) | 0 |
| Regulatory history | clean | 0 |
| Cyber | weak (no pen test) | 0.5 |
| Financial health | healthy (audited, positive equity) | 0 |
| Privacy | partial (GDPR, no DPIA/DPO) | 0.5 |
| **PEP** | **CFO is a PEP (ex-central-bank)** | **1** |
| Missing docs | penetration test report; **PEP EDD evidence** | 1.0 |

**Composite 2.4 → `CONDITIONAL`** (not DEFER, not APPROVE).

**The key call:** the CFO is a politically exposed person, the AML policy only
*states* PEP diligence is "on record," and no dedicated EDD file was attached.
ORION correctly does **not** count the policy mention as EDD evidence and
surfaces it as missing — exactly the "claimed vs. attached" rubric rule.

**Follow-up questions handed to the reviewer:**
1. "One or more key personnel are politically exposed persons (PEPs). Enhanced
   due diligence evidence including source of wealth documentation is required."
2. "Missing document required: penetration test report."
3. "Missing document required: PEP enhanced due diligence evidence."

**Auditability:** the run records `input_hash = e8ea2c1f…05d20`, the extracted
profile, all dimension scores, and the delivery outcome in `audit.jsonl`.
Re-running the same submission produces the same hash and the same decision —
anyone can verify the review months later.

## Why this is a pilot, not a production claim

- The worked example uses the deterministic mock extractor. The real-LLM held-out
  result is the generalization check (`python evaluate.py`).
- Human sign-off is still required: `review_status` starts `PENDING` and only a
  reviewer's `ACCEPTED`/`OVERRIDDEN` decision persists in the review store.
- See `docs/SDD.md` for scope/boundaries and `docs/PRIVACY_AND_RETENTION.md`
  for data handling.
